# スーパーややこしいシステム v.1.0.0

WebMCP のチュートリアル用サンプルアプリケーションです。

**「画面でやると地獄、エージェントに頼むと一瞬」** を体験するためだけに作られた、
わざと極限までややこしくした社内システム（経費精算・稟議ワークフロー）です。

- フロントエンドのみで完結します。サーバもデータベースもありません（永続化は `localStorage`）。
- Next.js の静的エクスポート（`output: 'export'`）で、GCP の Cloud Storage にそのまま置けます。
- エージェントは **Claude** を想定しています（接続手順は後述）。

デプロイ手順は [Deploy.md](./Deploy.md) を参照してください。

---

## 1. これは何のデモか

### ストーリー

あなたは営業部の佐藤さんです。8 月の出張精算を出さなければいけません。
経費は 3 件。ドルの立替えも 1 件あります。

この会社の経費精算システムは 1998 年から動いています。仕様はこうです。

- 入力は **7 ステップのウィザード**。途中で前のステップに戻ると入力内容が壊れることがある。
- 部門コードは **事業部(2桁)-部(3桁)-課(2桁)** の 3 段ドロップダウン。しかも課コードは連番ではなく欠番がある。
- 費目は **大分類 → 中分類 → 小分類** の 3 段カスケード。20 種類ある小分類ごとに金額上限とプロジェクトコード要否が違う。
- 外貨は **別表2 の社内レートを目で探して手入力**。円換算額も**電卓で計算して手入力**。1 円でもずれると弾かれる。
- 消費税は**内税方式で逆算して手入力**。軽減税率 8% は会議費のときだけ。
- 承認者 3 人は **別表3（承認マトリクス）と社員マスタを突き合わせて自分で特定**。システムは候補を出してくれない。
  しかも海外区分の費目か外貨が 1 件でも混ざると最終承認者が CFO に格上げされる。
- 合計が 5 万円を超えると、**別タブの「付表B」** が必須になる。
- 保存するのに**確認モーダルが 3 回**出る。
- そして提出時、**社内規程 R01〜R14 の 14 項目チェック**に 1 つでも違反していると提出できない。

明細 1 件あたり、おおよそ **25 回の入力操作**。3 件分やると 80 回近くになります。

### そこで WebMCP

このページは、同じ業務ロジックを **WebMCP のツールとして 13 本公開**しています。

Claude に一言頼むだけで済みます。

```
E1001 佐藤さんの 2026-08 の経費精算を作って。
8/3 に大阪出張の新幹線 28,600円、8/4 に国内宿泊 16,500円、
8/5 にサンフランシスコ出張の国際線 1,200 USD。
プロジェクトは PRJ-0042。規程を全部通した上で提出して、承認も最後まで通して。
```

レート参照も、円換算も、内税の逆算も、承認ルートの導出も、付表Bの要否判定も、
**すべてページ側のツールが規程どおりに実行**します。

> 重要: ツール側が検証を甘くしているわけではありません。
> 画面もツールも **まったく同じ検証関数**（`src/lib/domain/rules.ts`）を通ります。
> 違うのは「人間が手で埋めるか、ツールが規程どおりに埋めるか」だけです。

## 2. WebMCP とは

WebMCP（Web Model Context Protocol）は、**Web ページ自身が AI エージェント向けのツールを登録できる**ブラウザ API です。
W3C の Web Machine Learning コミュニティで仕様策定が進んでいます。

```js
document.modelContext.registerTool({
  name: 'create_request',
  description: '経費精算申請を作成する',
  inputSchema: { type: 'object', properties: { /* ... */ }, required: ['title'] },
  execute: async (args) => ({
    content: [{ type: 'text', text: '申請 RQ-0003 を作成しました' }],
  }),
});
```

ポイントは、**ツールの中身がそのページの JavaScript としてページのコンテキストで動く**ことです。
ログイン済みのセッション、画面の状態、クライアント側のロジックをそのまま使えます。
エージェントは DOM を推測してクリックする必要がなく、ページが用意した意味のある操作を呼ぶだけになります。

### このサンプルが前提にしている仕様の状態（2026-08 時点）

| 項目 | 内容 |
| --- | --- |
| 正式な設置場所 | `document.modelContext` |
| 非推奨エイリアス | `navigator.modelContext`（Chrome 150 で deprecate。互換のため残っている） |
| ツール登録 | `registerTool(descriptor)` |
| ツール解除 | 登録時に渡した `AbortSignal` を `abort()` する（`unregisterTool()` は仕様にない） |
| 一括登録 | `provideContext()` / `clearContext()` は **2026-03-05 にドラフトから削除済み**。使わないこと |
| 実行要件 | セキュアコンテキスト（HTTPS または `localhost`）でのみ利用可能 |

このリポジトリでは、実装ごとの差異を `src/lib/webmcp/registry.ts` で吸収しています。
仕様が動いてもここだけ直せば済むようにしてあります。

## 3. 動かす

```bash
npm install
npm run dev
# http://localhost:3000
```

`localhost` はセキュアコンテキスト扱いなので、開発中は HTTPS なしで WebMCP が使えます。

静的ビルドを確認する場合:

```bash
npm run build      # out/ に静的ファイルが出力される
npx serve out      # 任意の静的サーバでよい
```

### ブラウザに WebMCP 実装がない場合

このアプリは、`document.modelContext` が見つからなければ **ページ内蔵の最小フォールバック実装**を自分で入れます
（`src/lib/webmcp/polyfill.ts`。既存の実装があれば何もしない非破壊動作です）。

そのため、**拡張機能を入れていなくても**、画面右側の
「ツールを手動で試す」パネルから全ツールを実行して挙動を確認できます。
ただし内蔵フォールバックは**外部のエージェントからは見えません**。
Claude から実際に呼ばせるには次章の接続が必要です。

## 4. Claude から接続する

WebMCP のページに外部のエージェントを繋ぐには、**ブラウザ拡張機能（ブリッジ）** と
**ローカル MCP サーバ** を経由します。構成はこうです。

```
Claude (Desktop / Code)
   │  MCP (streamable-http)
   ▼
ローカル MCP サーバ  ← ここまでが Claude 側
   │  ネイティブメッセージング
   ▼
WebMCP ブリッジ拡張機能
   │  document.modelContext
   ▼
このページ（スーパーややこしいシステム）
```

### 手順

**① WebMCP ブリッジ拡張機能をブラウザに入れる**

Chrome / Edge に WebMCP のブリッジ拡張機能をインストールします。
拡張機能は `document.modelContext` をページに注入し、登録されたツールをローカル MCP サーバへ中継します。

**② ローカル MCP サーバを起動する**

```bash
npm install -g @mcp-b/native-server
mcp-b-native-server      # 既定で 127.0.0.1:12306 を待ち受ける
```

**③ Claude に MCP サーバを登録する**

Claude Code の場合:

```bash
claude mcp add --transport http webmcp http://127.0.0.1:12306/mcp
```

Claude Desktop の場合は `設定 → 開発者 → 設定を編集` から `claude_desktop_config.json` に追記します。

```json
{
  "mcpServers": {
    "webmcp": {
      "type": "streamable-http",
      "url": "http://127.0.0.1:12306/mcp"
    }
  }
}
```

**④ このアプリをブラウザで開いたまま、Claude に話しかける**

ページの右上バッジが `WebMCP: 接続可` になっていれば、拡張機能側の実装が検出されています。
`WebMCP: 内蔵` のままなら拡張機能が効いていないので、①②を見直してください。

> **注意**
> - ツールは**ページを開いているタブにしか存在しません**。タブを閉じるとツールも消えます。
> - WebMCP はセキュアコンテキスト必須です。`localhost` か HTTPS で開いてください（[Deploy.md](./Deploy.md) 参照）。
> - WebMCP のブリッジ実装（拡張機能・ローカルサーバ）は仕様と並行して活発に動いています。
>   パッケージ名やポートが変わっている場合は、各実装の最新の README に従ってください。
>   接続できない間も、画面右の手動実行パネルでチュートリアルは最後まで進められます。

## 5. チュートリアル

### 第 1 幕: まず、手でやってみる（所要 10〜15 分）

左サイドのメニューツリーから `起票（EXP010）` を開き、次の 1 件だけを入力してみてください。

| 項目 | 値 |
| --- | --- |
| 件名 | 8月度 出張精算 |
| 申請者 | E1001 佐藤 太郎 |
| 会計期間 | 2026-08 |
| 明細1 | 2026-08-03 / 特急・新幹線 / JPY 28,600 / PRJ-0042 |
| 明細2 | 2026-08-04 / 国内宿泊 / JPY 16,500 / PRJ-0042 |
| 明細3 | 2026-08-05 / 国際線 / USD 1,200 / PRJ-0042 |

途中で必ず詰まります。詰まってください。それがこのデモです。

- 明細3 の**適用レート**は? → `規程・マスタ照会 → 別表2` を開いて 2026-08 の USD を探す（**149.75**）
- **円換算額**は? → `1200 × 149.75 = 179,700`（円未満切捨）
- 明細3 の**消費税**は? → 国際線の既定税区分は `TEX`（非課税）なので **0**
- 明細1 の消費税は? → `floor(28600 × 10 ÷ 110) = 2,600`
- 明細2 は上限に引っかかります → 国内宿泊の上限は **18,000 円**。16,500 なのでセーフ
- 合計は 224,800 円 → **区分 C** → **付表Bが必須**（ステップ5）
- 承認ルートは? → 区分 C は `課長 → 部長 → 本部長`。
  でも明細3 が**海外区分**なので**最終承認者は CFO に格上げ**。
  社員マスタで E1001 の所属 `10-201-01` を引いて、
  課長 = **E1002**、部長 = **E1003**、CFO = **E3002** を自分で特定する

7 ステップ、確認モーダル 3 回。……ここまでやったら、次に進んでください。

### 第 2 幕: Claude に頼む（所要 30 秒）

同じことを、こう頼みます。

```
このページのツールを使って、E1001 佐藤さんの 2026-08 の経費精算を作ってください。

- 8/3 特急・新幹線 28,600円
- 8/4 国内宿泊 16,500円
- 8/5 国際線 1,200 USD

プロジェクトコードは全部 PRJ-0042。
付表Bが必要なら、理由は「西日本エリア顧客訪問およびSF拠点視察」、
訪問先は「大阪・サンフランシスコ」、同行者は「なし」、
事前承認番号は FIN-202608 で埋めてください。
```

Claude は概ねこう動きます。

1. `get_system_manual` — 規程と承認マトリクスを読む
2. `list_master_codes` — 費目コードと為替レートを引く
3. `create_request` — 1 回の呼び出しで申請を作る（レート・円換算・税額・承認ルートが自動で埋まる）
4. `validate_request_draft` — 規程 R01〜R14 を確認
5. `submit_request` — 提出

画面右下の「ツール呼び出しログ」に、呼び出しが 1 行ずつ流れるのが見えます。
中央の画面も一緒に動きます（`navigate_ui` ツールで Claude が画面を切り替えるため）。

### 第 3 幕: 人間には面倒すぎる仕事を頼む

ここからが本番です。UI では現実的に無理な規模を頼んでみてください。

**(a) ワークフローを最後まで通す**

```
いま作った申請を、承認ルートの順番どおりに最後まで承認して、
2026-08 の月次締めまで実行してください。
```

承認は「現在の承認者」しか実行できません（順番を飛ばすと弾かれます）。
Claude は承認ルートを読んで、E1002 → E1003 → E3002 の順に `approve_request` を呼びます。

**(b) 壊れたデータを直す**

初期データの `RQ-0002` は、わざと 6 件の規程違反を含んでいます。

```
RQ-0002 の規程違反を全部直して、提出できる状態にしてください。
金額は変えずに、規程の範囲で通るように調整してください。
```

`validate_request_draft` が「どの条文の」「どこが」「どう直すか」まで返すので、
Claude は往復せずに `update_request` で修正できます。

> ヒント: 宿泊費の上限超過は金額を変えないと通りません。
> Claude がどう説明してくるかを見るのが面白いところです。

**(c) 一括投入**

```
E2001 小林さんの 2026-08 の経費を 3 件分、別々の申請として登録してください。
内容は適当に、区分 A / B / C がそれぞれ 1 件ずつになるように作り分けてください。
```

区分をコントロールするには合計金額を逆算する必要があります。承認ルートも区分ごとに変わります。
人間なら 20 分。ツールなら数回の呼び出しです。

## 6. 公開しているツール

| ツール名 | 種別 | 内容 |
| --- | --- | --- |
| `get_system_manual` | 読取 | 業務フロー・規程 R01〜R14・承認マトリクス・システム基準日 |
| `list_master_codes` | 読取 | 組織 / 社員 / 費目3階層 / 為替レート / 税区分 / 承認マトリクス |
| `list_requests` | 読取 | 申請一覧（状態・申請者・期間・件名・承認待ち者で絞込） |
| `get_request` | 読取 | 申請 1 件の全項目 + 承認履歴 + 現在の規程違反 |
| `validate_request_draft` | 読取 | 既存申請 or 未登録の下書きを R01〜R14 で検証（状態は変えない） |
| `create_request` | 更新 | 申請を作成。レート・円換算・税額・承認ルートを自動計算 |
| `update_request` | 更新 | 起票中・差戻しの申請を修正し、再計算 |
| `delete_request` | 破壊 | 申請を削除 |
| `submit_request` | 更新 | 提出。規程を全て満たしていないと弾く |
| `approve_request` | 更新 | 承認 / 差戻し。承認ルート上の現在の承認者のみ実行可 |
| `run_month_end_close` | 破壊 | 月次締め + 部門別・費目別の集計レポート |
| `navigate_ui` | 更新 | 画面表示を切り替える（人間に作業を見せるため） |
| `reset_demo_data` | 破壊 | デモデータを初期化 |

各ツールの `inputSchema` と説明文は `src/lib/tools/index.ts` にあります。

### ツール設計で意識したこと

このサンプルは「WebMCP を使ってみた」以上に、**エージェントに使わせるツールの設計例**を意図しています。

- **画面の操作ではなく、業務の単位でツールを切る。**
  `click_next_button` のようなツールは作らない。`create_request` は 7 ステップ分をまとめて受け取る。
- **エラーは「直し方」まで返す。**
  「R05 違反」ではなく「円換算額を 179,700 に修正してください」と返す。往復が減る。
- **読取専用ツールを用意して、推測させない。**
  レートも承認マトリクスも `list_master_codes` で引ける。エージェントに暗記させない。
- **`annotations.readOnlyHint` / `destructiveHint` を正しく付ける。**
  エージェント側が慎重に扱うべき操作を区別できる。
- **検証ロジックを UI と共有する。**
  ツール専用の抜け道を作らない。

### 登録のしかた（実装の核心）

```ts
// src/lib/webmcp/useWebMCP.ts
useEffect(() => {
  initWebMCP();                                   // document.modelContext を確保
  const controller = new AbortController();
  registerTools(ALL_TOOLS, controller.signal);    // まとめて登録
  return () => controller.abort();                // 解除は abort（仕様どおり）
}, []);
```

## 8. 制約・既知の注意点

- **サーバはありません。** データはブラウザの `localStorage`（キー `syys.v1`）にのみ保存されます。
  別のブラウザ・別の端末とは共有されません。
- **システム基準日は `2026-08-20` に固定**しています（`src/lib/domain/masters.ts`）。
  実時刻を使うと未来日チェック R03 の結果が日によって変わり、チュートリアルが再現しなくなるためです。
- 会計期間は `2026-07` / `2026-08` / `2026-09` の 3 つだけです（為替レート表がこの範囲のため）。
- **WebMCP はセキュアコンテキスト必須**です。HTTP で配信すると `document.modelContext` は使えません。
- 内蔵フォールバック実装は、あくまで画面内で挙動を確認するためのものです。
  外部エージェントとの接続にはブリッジ拡張機能が必要です。
- npm の WebMCP パッケージ（`@mcp-b/webmcp-polyfill` 等）には**あえて依存していません**。
  仕様の変化を `src/lib/webmcp/` の 4 ファイルに閉じ込めるためです。
  公式パッケージを使いたい場合は `polyfill.ts` を差し替えてください。
